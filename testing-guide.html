Section 12: Securing Gateway with Keycloak & RBAC

Keycloak: 8090 OAuth2 Resource Server Role: ADMIN
Professor's Target & Learning Objective
Secure the microservice architecture using an external OAuth2 / OIDC Identity Provider (Keycloak). Configure Spring Cloud Gateway as an OAuth2 Resource Server validating JWT tokens via JWK Set URI. Extract roles using custom KeycloakRoleConverter and enforce Role-Based Access Control (RBAC): • /api/tournaments/** requires ROLE_ADMIN. • /api/teams/** requires authenticated.
TOKEN Test 1: Obtain Access Token from Keycloak
Client Credentials
Start Keycloak
docker run -d -p 8090:8080 --name keycloak -e KC_BOOTSTRAP_ADMIN_USERNAME=admin -e KC_BOOTSTRAP_ADMIN_PASSWORD=admin quay.io/keycloak/keycloak:26.3.4 start-dev
Fetch Token via cURL / Postman
curl -X POST http://localhost:8090/realms/master/protocol/openid-connect/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=client_credentials&client_id=dept-app&client_secret=YOUR_CLIENT_SECRET"
SECURITY Test 2: Test 401 Unauthorized vs 200 OK with Token
RBAC Verification
Call without Token (Rejected)
curl -i -X GET http://localhost:8888/api/tournaments/PL
Expected 401 Response
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer
Call with Valid ADMIN Token (Accepted)
curl -X GET http://localhost:8888/api/tournaments/PL -H "Authorization: Bearer YOUR_ACCESS_TOKEN"
  • Without token: Returns 401 Unauthorized.
  • With token containing ADMIN role: Returns 200 OK.
  • Remove ADMIN role from client in Keycloak → re-request token → call returns 403 Forbidden!
